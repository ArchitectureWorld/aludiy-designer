# AluDIY Designer v0.1.6-alpha Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add exact node/member editing, reference-dimension feedback, and release metadata for the first remotely updatable Blender extension build.

**Architecture:** Keep all authoritative mutation logic in the Blender-independent core. Blender operators parse user input, call core commands, persist the project JSON, rebuild disposable caches, and restore selection. The viewport overlay reads the same project model and draws non-persistent reference dimensions.

**Tech Stack:** Python 3.11+, pytest, Blender 5.2 Extension API, GitHub Actions / Pages.

**Spec:** `docs/superpowers/specs/2026-10-15-aludiy-v0.1.6-precision-editing-design.md`

## Global Constraints

- Extension ID remains `aludiy_designer`.
- Manifest version is `0.1.6`; UI version is `0.1.6-alpha`.
- `src/aludiy_core` must not import `bpy`.
- Project coordinates remain millimetres; Blender conversion occurs only in the adapter.
- Generated line and solid objects remain disposable caches.
- All engineering edits use Blender Undo and preserve native delete shortcuts.

## Review Focus

- Shared-node edits must increment every affected member revision exactly once.
- A failed edit must not persist a partial project or zero-length member.
- Negative coordinates and delta expressions must parse correctly.
- Selection must survive scene rebuild for both Member and Node edits.
- Overlay drawing must tolerate hidden/off-screen endpoints without raising.
